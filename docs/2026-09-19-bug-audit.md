# Bug audit — 2026-09-19

Status: fixed and verified locally. No commit, push, Worker deployment, production database change, or account change was made during this audit. Existing uncommitted work was preserved.

## Bugs fixed

| Issue | Change and evidence |
| --- | --- |
| Mobile browser toolbar changes resized the background canvas. | The fixed background uses `100lvh` with a `100vh` fallback. Large viewport units keep the canvas stable while browser controls retract. At 390px wide, expanding a long description left the background height unchanged and produced no horizontal overflow. A physical mobile-browser toolbar check remains necessary. |
| Member links could stay stale indefinitely in an open tab. | Stream refresh now refreshes member information after one hour, or after a missing/failed member fetch. A test checks that ordinary refreshes reuse it and that it is fetched again after expiry. |
| Multiple YouTube records could select an older live broadcast or overwrite a live record with a non-live one. | The store consistently selects a live broadcast first, then the newest record within that category. Regression coverage supplies out-of-order and conflicting records. Twitch login matching also ignores case and surrounding whitespace. |
| Clearing the video cache left an in-memory copy available to restore. | Successful clearing now removes that copy while keeping the currently displayed list usable. A remount test verifies a fresh request. |
| A tab with a smaller archive could overwrite another tab's larger saved archive. | IndexedDB saves now read and merge in one transaction, deduplicate video IDs, and preserve the newest head's continuation cursor. Tests cover smaller, concurrent, and older writes. |
| Malformed API or browser-cache records could reach rendering code and crash it. | Shared runtime validation rejects malformed records and preserves the last successful response. Tests cover corrupt cached and network data for uploads, members, and streams. |
| A blocked IndexedDB upgrade could leave a delayed connection open. | Opens time out, and abandoned requests close their connection if they eventually succeed. A regression verifies a later database upgrade can proceed. |
| Repeating pagination cursors could keep Load all running indefinitely. | Each loading pass detects any repeated cursor, including a multi-page cycle, and reports a retryable error. A test verifies the request loop stops. |
| An already-open sharing panel could retain an outdated URL after filters changed. | The share URL now follows the current filters and creator selection. The browsing regression verifies the URL changes when a favorite is removed. |
| Database failures on public YouTube and member routes were reported as 404 responses without consistent CORS. | Errors now reach the shared JSON 500 handler, with CORS and `Cache-Control: no-store`. Isolated D1 integration tests simulate unavailable tables and verify both the failure response and recovery. |

Unused backend bindings, imports, counters, and an empty mapper were also removed after the static checks identified them.

The mobile CSS choice follows the [MDN explanation of large viewport units](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/length#large_viewport_units): these units remain stable while retractable browser UI changes, but still respond to an actual viewport resize such as rotation.

## Remaining limitations and follow-ups

1. **Verify the mobile toolbar on a real phone.** Desktop viewport emulation cannot faithfully reproduce Safari/Chrome browser controls retracting. Also check rotation; an actual orientation change should resize the background.
2. **Older cached metadata can remain stale.** The newest ten uploads refresh normally, but old edited/deleted/private videos do not have a backend revision or deletion feed. Reliable archive reconciliation needs a separately scoped backend design; this audit does not silently reload everyone's archive.
3. **Receipt time is not upstream freshness.** Current labels describe when the browser received an API response. They cannot prove the backend recently checked YouTube or Twitch. Source health and authoritative upstream-check timestamps remain a backend follow-up.
4. **Legacy filtered-query code is unused.** The optional member filters in `getAllVideos` are not applied by that legacy database helper. Current public callers do not pass those filters. Remove or implement that unused interface before introducing callers that depend on it.

These checks are a focused bug review, not an exhaustive security or load audit. Existing frontend utility changes and the previously added backend stale-live fix were included in the test runs, but have not been deployed by this audit.
